# Contributing to MacDock

## Workflow

1. Start from an up-to-date `main` branch.
2. Create a focused feature, fix, or research branch.
3. Associate meaningful work with a GitHub Issue when practical.
4. Keep changes small and reviewable.
5. Run the relevant local validation.
6. Open a pull request using the repository template.
7. Merge only after required CI checks pass.

## Branch naming

Use concise English names such as:

- `research/bonjour-discovery`
- `feature/dock-persistence`
- `fix/reconnect-state`
- `docs/update-mvp-scope`

## Commit messages

Use imperative English commit messages with a focused scope, for example:

`docs: define initial MVP scope`

## Validation

Do not report a validation as successful unless the command completed successfully and its result was reviewed.

For the detailed task, documentation, Project, and Issue synchronization procedure, see [Development Workflow](docs/DEVELOPMENT_WORKFLOW.md).
